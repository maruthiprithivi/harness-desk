# Harness desk

A local browser dashboard and advisory sidecar for understanding coding-agent setups. Requires Node.js 22 or newer. The app needs no runtime packages, remote database, Python environment or desktop framework. This is a development preview with macOS validation; Windows support and the public package release are in progress.

**Start here:** [Read the illustrated user guide](docs/user-guide.md) · [Watch or download the explainer video](https://github.com/maruthiprithivi/harness-desk/raw/refs/heads/main/docs/assets/explainer/harness-desk.mp4)

Get the source and run it locally:

~~~sh
git clone https://github.com/maruthiprithivi/harness-desk.git
cd harness-desk
npm start
~~~

Open http://127.0.0.1:4319. On macOS you can use start.command. On Windows use start.cmd. These launchers and npm start leave the server running in the background after the terminal closes, wait for readiness, and reuse an existing instance. They print its PID and startup log at data/runtime/server.log. The log is operational output, outside age-based report archiving. To stop it, use kill with the printed PID on macOS, or Stop-Process -Id with that PID in Windows PowerShell. After restarting your computer, run the launcher again.

For a foreground development session, run node server.mjs and keep that terminal open. The service listens only on loopback. To choose a port, set PORT before launching. HARNESS_DATA_DIR changes the generated-data location, default ./data.

Only one server can use a data directory, even on different ports. A dead server's PID lock is recovered on launch. If startup itself was forcibly interrupted while acquiring that lock, startup fails closed and prints the runtime/startup-lock directory to inspect before retrying.

## Data and privacy

Settings and the artifact manifest are JSON. Generated snapshots, observations, journal excerpts, imported audit records, proposals, reports and conversations remain in data/. No secret values or raw transcripts are intentionally retained. Redaction catches common credential forms, not every possible secret. Review the context preview before sending it to an agent provider.

The gap ledger is private, pinned JSON and Markdown under data/gaps/, protected from age-based archiving. It deduplicates observation IDs with a rolling cache and bounds records, event history and conversation links; it is not a complete activity log. Opening or refreshing Gaps & pitfalls never invokes a provider or changes external settings, scripts or agent configuration.

Inventory and loading-map scans keep JSON/TOML settings, MCP configuration and scripts metadata-only. Opening a file explicitly in the protected editor reads that one body; this does not add its contents to loading inference or automatically send them to an agent. File backups remain local under data/backups/files/ and are protected from age-based archiving.

Protected documents are withheld in full, including multiline sensitive values and recognized SOPS documents. File version checks catch edits before the final replacement, but Node cannot atomically compare and replace a file. Avoid simultaneous editing of the same file in another app; the original backup is preserved locally.

Authentication files are never read. CLI sign-in probes use the installed CLI. Dispatch uses the selected model or its CLI default; the utility does not infer a cheap model from a model name. Configure an explicit cheaper model per task/repository only after verifying it is available to that agent.

The sidecar does not automatically change harness settings, archive source skills, enforce external hooks, execute proposed scripts, submit journal changes or schedule itself at login. Read [PRODUCT.md](PRODUCT.md) for the review and verification workflow behind those changes.

## Public repository

The public upstream is [harness-desk](https://github.com/maruthiprithivi/harness-desk). Publish reusable source and synthetic fixtures only. Local generated data, journal sources, agent configuration, screenshots, credentials and the local task ledger are ignored. Keep them out of public issues, pull requests, logs and artifacts too.

Before publishing, run `npm run check:public:source` to inspect source candidates, `npm run check:public` for the Git index, and `npm run check:public:history` for reachable commits and annotated tags. The checks reject unexpected paths before reading their contents and report rule names without matched values. They also reject personal home paths and private email addresses. Review the outgoing diff and history because patterns cannot identify every kind of private prose.

The hooks in .githooks run these checks at commit and push time. The push check reads Git's outgoing object IDs, including objects not reachable from local branches. Install the hooks in the local Git hooks directory only after checking for existing hooks. Keep existing global hooks configured and ensure they preserve Git's push input when chaining to repository hooks. Hooks can be bypassed, so the explicit checks remain required. Use a public GitHub noreply commit email. Selecting an upstream does not itself publish code.
