# Product decisions and next verification

The [product brief](docs/designs/harness-desk-product-brief.md) records the 2026-10-13 interview, intended user journey, approval defaults, verification requirements and design references. It defines the next product direction; the implementation notes below describe existing behavior and earlier decisions.

The useful unit is a scoped recommendation with evidence and a measured outcome. A score that mixes every agent and every repository does not tell you what a fresh session actually loads.

## Readable workspace design

Use cool neutral surfaces, a slate sidebar and a restrained teal accent. System sans-serif fonts keep the app local, portable and consistent across navigation, diagrams and editors. Body text is 16px and supporting text is at least 14px. The beginner screen leads with the next task and one persistent repository/agent selector pair. Setup assistance and supporting evidence expand on demand. File groups and counts use dividers rather than nested cards. Keep inferred loading, unknown values and source-review actions visible or explicitly reachable. Test keyboard focus, long paths and narrow screens whenever changing this hierarchy.

## Context age and continuous operation

File age is a storage policy, not proof that memory is stale. Mark decisions with scope, source, last validation, expiry conditions and superseding decisions. Retrieve only relevant lessons for each request. Do not repeatedly paste the entire journal or all conversations into context.

Start with bounded interval scans and a drift report. Add debounced file-change triggers for new skill/MCP packs, journal commits and supported invocation events. A monthly audit should compare the same baselines, list new repeat candidates and confirmed recurring failures, flag unknown telemetry, draft journal changes, and stop before applying migrations. Continuous operation should produce reviewable proposals, not repeated frontier-model calls.

1. Scan a fixture global home and two repositories. Verify global skills and repository rules have different scope; secret and symlink fixtures are excluded.
2. Record fresh-session context in a chosen repo. Override its budget and verify another repo still inherits global defaults.
3. Start a selected-item chat, inspect the preview, then send a follow-up. Verify fixed repo/agent scope and persisted history after restart.
4. Import repeated-work evidence and draft a script. Verify qualification thresholds, provenance and scope before accepting it.
5. Preview old generated files, pin a conversation and archive. Verify source files and settings remain intact and archived bytes remain counted.
